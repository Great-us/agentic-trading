# 二号 Paper 盘 · 主题轮动实验设计

**日期**：2026-08-23
**地位**：本文件是二号盘（新开 Alpaca paper 账户）上"相对强度主题轮动"
实验的唯一依据。一号盘照常运行，本实验**不改动现有系统的任何代码与配置**。
二号盘开通前，本文档只做纸面设计；开通后按第 4 节清单搭建。

## 0. 预期落差——先读这一节再决定要不要做

RS 用的是 **20/60 日中期动量**，名单换手是**周级别**的：连续多个交易日名单
几乎不变才是常态。这是对短线圈"日内题材每天换一批"做法的**有意偏离**：

- 日间级别的"什么会被炒起来"事后看清晰、事前近似随机——靠它选股基本是在
  交易随机性；
- 本实验回答的是一个可回答的问题："**最近谁在被持续买入**"。这是学术上少数
  站得住的因子（横截面动量），主题只是对排名结果的事后命名，不是预测；
- 因此，**不要用"名单没怎么变"判定实验失败**。名单稳定恰恰说明动量在延续。
  实验成败的判据在第 5 节，与换手率无关。

## 1. 实验定位与边界

- 一号盘照常运行、零改动；本实验全部在二号盘独立目录内进行。
- 核心命题：每晚用机械的相对强度排名决定次日活跃名单，验证
  "轮动池 + 全套既有风控" 相对 "固定池" 是否产生增量信息。
- 选股 100% 机械（RS 排名），LLM 只负责给上榜名单打行业/主题标签存档，
  **不参与任何选股或择时决策**。

## 2. 两个决策点的精确规格

### 晚间轮（T-1 收盘后，建议 ~20:00）

数据快照口径：**settled bar**（不含当日形成中的 bar）。

1. 拉当前候选池全部名字的日线与 SPY 日线；
2. 计算每名的超额收益：
   - `excess_20d = ret(20d) − ret_SPY(20d)`
   - `excess_60d = ret(60d) − ret_SPY(60d)`
   - `RS = 0.5 × percentile(excess_20d) + 0.5 × percentile(excess_60d)`
     （percentile 在候选池横截面内计算）
3. 流动性门槛复验：20 日 ADV ≥ $20M（与 risk.yaml 一致），不过者除名；
4. 取 **Top-N，N=10**（max_open_positions=8 留缓冲）为次日活跃名单；
5. LLM 按 GICS 行业给名单打主题标签（如"HBM 存储 / 光模块 / 生物科技"），
   与名单一起存档到 `research/p2/rosters/YYYY-MM-DD.md`。

### 午间轮（T 日 12:00–13:00）

数据快照口径：**含当日形成中的 bar**（同 fast-tier 的 Alpaca feed 口径）。

1. 同一公式重算一遍；
2. 变化处理带**迟滞**：
   - 新进者须"晚间 + 午间连续两次上榜"才允许被买入（单日冲榜不算数，
     与 min_intraday_confirm_scans 的防抖哲学一致）；
   - 跌出者若已持仓**不强卖**——走既有止损 / trailing 规则自然退出，
     避免轮动变绞肉机；
3. 输出 diff 记录（进了谁、出了谁、各自 RS 变化）追加到当日 roster 文件。

**其余所有时间不产生任何交易决策。** 盘中看到"热点"想临时加票，唯一合法
通道是下一轮午间迟滞规则。

### 候选池刷新机制（防退化）

252 候选池是 2026-08-22 筛出来的。池子永不刷新，实验会退化成
"在八月的赢家里打转"。规定：

- **每季度重跑一次全市场筛选**：同一套 SA Quant 门槛（SB/Buy）+
  mcap ≥ $5B + ADV ≥ $20M + Alpaca 可交易性验证；
- 刷新日志必须记录：筛选日、通过数量、新旧池 diff（新增/剔除名单）；
- RS 排名始终跑在**当前池**上，跨季不拼接旧池的历史排名。

## 3. 入场与风控：沿用一号盘全套机制

quant 阈值（buy_threshold 等）、等风险仓位、ATR 止损、trailing、sector cap、
risk-off 减半、相关性减半、gap-veto、broker 端保护性 stop——**全部照搬，
一个参数不改**。本实验唯一变量是宇宙来源（轮动池 vs 固定池），其他全部冻结，
保证归因干净：跑赢了只能归因于轮动，跑输了也只能归因于轮动。

## 4. 二号盘落地清单（开通后执行）

> **独立目录是硬性前提，不是建议。** 一号盘 P0 加固后的 `data/cycle.lock`
> 是按工作目录加锁的 OS 锁——二号盘若在同一目录运行，会被锁直接挡掉。
> 必须完整克隆仓库到独立目录，例如 `C:\Users\helow\Documents\Trading-P2`。

1. 注册新 Alpaca 账户，生成 paper API key/secret；
2. 克隆仓库到独立目录，`python -m venv .venv && pip install -r requirements.txt && pip install -e .`；
3. 独立 `.env`（二号盘密钥；分析师后端配置可复制一号盘的）；
4. 独立 `data/journal.db`、`logs/`（随独立目录天然隔离）、独立
   `config/watchlist.yaml`（由每晚轮生成，初始为空由首轮填充）；
5. 计划任务命名 `AgenticTradingP2` / `P2FastScan`，深周期错峰至 **9:50**
   执行，避免与一号盘同时抢行情与 LLM 配额；
6. 已知需要的小改造点（**待二号盘开通后再实施，本次不做**）：
   - roster 生成脚本（晚间/午间轮各一次，读池→算 RS→写 watchlist 与档案）；
   - 两盘对比报表（持仓重叠度、净值相关系数，见第 5 节）。

## 5. 评估协议（预注册，写完即冻结）

- 最短运行 **6 个日历月**才做第一次正式判读；此前一切波动按噪音处理；
- 对照组：SPY、exposure-matched SPY+cash、以及**一号盘同期表现**；
- 主要指标：Calmar、MaxDD、相对 exposure-matched SPY 的超额收益；
- **增量信息检验（防止实验退化为一号盘复制品）**：
  - 每日记录两盘持仓重叠度 = 共同 symbol 数 / max(|P1|, |P2|)；
  - 滚动计算两盘净值日收益的 60 日相关系数；
  - 判定线：持仓重叠长期 **>70%** 且收益相关性持续 **>0.95** →
    判定"轮动没有产生增量信息"，无论二号盘自身盈亏如何；
- 降级条款：连续两个季度跑输对照组 → 实验判负，结论回归固定池；
- 纪律引用 HOLDOUT-LEDGER：不许中途改 RS 参数（窗口、权重、N）之后
  引用改动前的数字。

## 6. 明确禁止事项

- 禁止盘中看到"热点"临时加票（唯一例外通道是午间轮的迟滞规则）；
- 禁止因某主题连续上涨而放松 Tech cap 或相关性减半——那是另一个风险
  决策，必须走完整评审并修订本文档；
- 禁止把一号盘的历史回测数字（2007 起的 +15.1% CAGR 等）引用为本实验的
  预期收益；
- 禁止跳过季度池刷新继续用旧池排名。

## 附录 A：RS 手算示例（真实数字，任何人可复核）

以 2026-08-21 收盘为快照（yfinance settled bar，126 根日线取尾）：

| 名字 | last | ret(20d) | ret(60d) | excess_20d | excess_60d |
|---|---:|---:|---:|---:|---:|
| SPY | 765.72 | +3.6% | +2.3% | — | — |
| MU | 966.78 | +5.0% | +4.1% | +1.4pp | +1.8pp |
| VEEV | 247.90 | +33.1% | +56.4% | +29.5pp | +54.1pp |

以 VEEV 为例：

```
ret(20d)  = close[-1]  / close[-21] − 1 = 247.90 / 186.2x − 1 ≈ +33.1%
excess_20 = +33.1% − SPY 的 +3.6%      = +29.5pp
excess_60 = +56.4% − SPY 的 +2.3%      = +54.1pp
RS        = 0.5 × percentile(+29.5pp 在 252 名中) 
          + 0.5 × percentile(+54.1pp 在 252 名中)
```

percentile 的含义：把 252 个名字的同指标排序后取位置分位。若 20 日超额
+29.5pp 只输给约 8 个名字，则该项 percentile ≈ 96%。两项加权后与全池比较，
Top-10 上榜。（MU 这种个位数超额的名字大概率落榜——这正是机制在表达
"最近被持续买入的程度不如别人"。）
